# 20260929 登録済みの記録を修正できるようにする

## 要望
- 記録画面で、登録済みの記録を削除はできるが修正できない。修正できるようにする

## 決定事項（利用者に確認済み）
- 体重・食事を、すでに記録がある日（食事は日・区分）に変える修正はエラーで止める（上書き・置き換えはしない）

## 方針
### API
- `PATCH /records/:recordId`（本文は作成と同じ形。種類ごとの必須項目・未来の時刻の拒否・tz も同じ検証を使う）
  - 対象は自分の家族のこどもの記録だけ（削除と同じ条件）。それ以外・存在しないものは 404
  - 種類（type）は変えられない。本文の type が記録と違えば 400
  - 体重・食事は「こども × 日（× 区分）で 1 件」を保つ: 自分以外に同じ日（・区分）の記録があれば 409（`code: 'DUPLICATE_RECORD'`）
    - 作成と同じロック・同じ検索（自分を除く条件を足す）を使い、検索処理は作成と共通化する
  - 記録者（createdBy）は変えない
  - 応答は更新後の記録（一覧と同じ形）

### アプリ
- 記録画面の各行をタップすると修正画面を開く（削除ボタンは今のまま）
- 入力画面を「新規」と「修正」で共用する
  - 修正では、日時・終了時刻・量・体重・区分・メモを記録の値で埋める。タイトルは「〇〇を修正」
  - 体重・食事で、選んだ日（・区分）に**別の**記録があれば、保存前に「この日の体重はすでに記録されています。日付を変えるか、そちらの記録を修正してください」と出し、保存ボタンを押せなくする（サーバーの 409 でも同じ文言を出す）
  - 修正では、他の記録の内容で入力欄を埋め直す動き（新規のときの上書き用）はしない
- 保存したら一覧・グラフを再取得して画面を閉じる（新規と同じ）

## 実装メモ（計画からの追加）
- 日付・区分を変えない修正は重複の確認をしない（以前から同じ日に重複している体重・食事も、値は直せるように）。アプリも同じ判定
- 修正の本文は全項目の置き換え（メモを省くと消える。アプリは常に全項目を送る）
- 移動先の日の記録を読み込み中は、重複か分からないので保存ボタンを押せない
- 作成と修正で、項目の組み立て（recordFields）・ロック（lockChild）・同じ日の検索（findSameDay）を共通化

## 検証
- API: `npm run lint`・`npm run test:e2e`（37 件）・`npm run build` 成功。`npm run test` は既存の 1 件（env.spec.ts の Gemini の既定モデル）のみ失敗
  - e2e: ミルク・睡眠の修正、終了が開始より前・未来の時刻は 400、種類の変更は 400、体重を空いている日へ移すと成功・記録のある日へは 409、同じ日のまま値を直すのは成功、以前からの重複も同じ日なら直せる、食事の区分の変更と 409、他の家族の記録・存在しない記録は 404
  - 1 回だけ新しいテストの作成が 404 で失敗したが、その後 5 回続けて成功。同じ e2e 用 DB に対して e2e が同時に走り、後から始まった方の準備処理（全削除）がデータを消した可能性が高い（コードの問題ではない）
- アプリ: `flutter analyze` 問題なし、`flutter test` 全件成功（52 件）
  - 行タップで修正画面・初期値、自分自身は重複扱いしない、埋まっている区分への変更で保存不可、保存で update が呼ばれ画面が閉じる、409 の文言
- API 契約テスト: 成功（ミルクの量・食事のメモの修正を含む）

## レビュー結果
code-reviewer・security-reviewer とも Critical・High はなし。

### 対応したもの
- Medium: 以前からの重複データが値を直せない → 日付・区分を変えないなら重複の確認をしない
- Medium: 修正の保存処理のテストがない → 偽のリポジトリで保存・409 の表示をテスト
- Low: 確認と更新の間に家族から外れた場合に更新できてしまう（security-reviewer）→ 更新の条件にも家族の条件を入れた
- Low: 読み込み中に重複の確認がすり抜ける → 読み込み中は保存不可
- Low: 意味の薄いテストの確認を削除、PATCH が全項目の置き換えであることをコメントに記載
- 再レビュー（code-reviewer 2 回目）: 移動先の日の記録の取得に失敗すると保存できないまま → 保存不可は読み込み中だけ（失敗時はサーバーの 409 で止める）。以前からの重複を同じ日のまま直せることのアプリ側のテストを追加（計 53 件）

### 残るもの（対応しない・利用者判断）
- 家族の誰でも他の人の記録を修正できる。記録者の表示は最初の人のまま（削除と同じ方針）
- 同時に同じ記録を修正した場合は後から保存した方が残る（楽観的ロックなし）
- 一覧の行を素早く 2 回タップすると修正画面が 2 枚開く（新規の画面と同じ作り）
- e2e の新しいテストは 1 つが長い（分割は見送り）

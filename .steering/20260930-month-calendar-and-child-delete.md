# 20260930 記録の月間カレンダーと、こどもの削除

## 要望
1. 記録画面に、1 か月の記録をカレンダーでまとめて見る画面を追加する
   - 開くのが遅くても「読み込み中」だとわかるようにする
2. 「こどもの情報を編集」画面に削除ボタンを付ける
   - こどもが 0 人になる削除はブロックする

## 1. 月間カレンダー

### 画面の流れ
- 記録画面の日付の見出し（`M月d日(E)`）の横にカレンダーのアイコンを置き、タップで月間カレンダー画面（`/records/calendar`）を開く
  - 最初は、記録画面で表示している日の月を出す
- カレンダー画面
  - 上に「◀ 2026年9月 ▶」。左右スワイプでも月を移動できる（記録画面と同じ PageView）。今月より先には進めない
  - 7 列（日〜土）のマス。各マスに日付と、その日の要約を小さく出す
    - 🍼 ミルクの合計 ml、💤 睡眠の合計時間、⚖ 体重（その日に記録があれば）、🍚 食事の件数
    - マスに入りきらない分は省略。記録がない日は日付だけ。今日には枠を付け、未来の日と生まれる前の日は薄くする
  - カレンダーの下に、月のまとめ（ミルクの 1 日平均、睡眠の 1 日平均、月初と月末の体重の差、記録した日数）
  - 日付をタップすると、下にその日の要約を出し、「この日の記録を見る」ボタンで記録画面のその日に移る（前の画面に戻り、ページもその日へ動かす）

### 読み込み中の見せ方（要望の重点）
- カレンダーの枠（日付のマス）は、データを待たずにすぐ出す。空の画面や、スピナーだけの画面にはしない
- 読み込み中は
  - 月の見出しのすぐ下に、細い進捗バー（LinearProgressIndicator）を出す
  - 各マスの要約の部分に、灰色の仮の棒（プレースホルダー）を出し、ゆっくり明滅させる
  - 月のまとめの欄にも「読み込み中…」と出す
- 月を切り替えたとき：前の月のデータは見せない（別の月の数字と取り違えないため）。新しい月の枠とプレースホルダーを出す
- 取得済みの月は、戻ったときにすぐ出す（画面から外れてから 5 分間はキャッシュする。記録の追加・修正・削除とログアウトで捨てる）
- 失敗したとき：マスの下にエラー文と「再読み込み」ボタン。枠は出したままにする
- 下に引っ張ると再取得（記録画面と同じ）

### API（バックエンドに 1 本追加）
- `GET /children/:childId/stats/daily-summary?from=YYYY-MM-DD&to=YYYY-MM-DD&tz=Asia/Tokyo`
  - 既存の milk-daily と同じ形（範囲は 93 日まで、日付は tz で区切る、SQL で集計）
  - 返す値（記録がある日だけ）: `date`, `milkMl`, `milkCount`, `sleepMinutes`, `sleepCount`, `weightG`（その日の最新 1 件）, `mealCount`
  - 睡眠は「始まった日」に数える（記録画面の日別一覧と同じ区切り）
- 既存の一覧 API（1000 件まで）を 1 か月分取ってアプリで集計する案もあるが、記録が多い家庭では 1000 件を超えて数字が欠けるため、集計 API にする

## 2. こどもの削除

### アプリ
- 編集画面の一番下（保存ボタンの下）に、赤い「このこどもを削除」ボタン
- 押すと確認ダイアログ：「◯◯ちゃんを削除しますか？ 記録・AI の分析・習慣レポートもすべて削除され、元に戻せません」
- 削除したら、こどもの選択を外し（残ったこどもの先頭が選ばれる）、一覧と記録の表示を取り直してホームに戻る
- その家族のこどもが 1 人だけのときは、ボタンを押せなくして「こどもが 1 人だけのときは削除できません」と添える

### API
- `DELETE /children/:childId` で、家族のこどもが 1 人だけなら 409 `LAST_CHILD` を返す
- 同時に 2 人を削除して 0 人になるのを防ぐため、こどもの登録と同じ家族ごとのロックを取り、人数の確認と削除を 1 つずつ行う
- アプリの `errorMessage()` に `LAST_CHILD` の文言を追加する（今のままだと未知の 409 は「このメールアドレスは既に登録されています」になるため）

### 決めたこと（確認済み）
- 「0 人」は家族ごとに数える。「その家族のこどもが 0 人になる削除」をブロックする
  - 複数の家族に所属していても、家族ごとに 1 人は残る
- 削除できるのは家族のメンバー全員（管理者に限らない。記録の編集と同じ）

### タスク
- [ ] API: 削除時の人数確認とロック、409 `LAST_CHILD`
- [ ] API e2e テスト: 1 人だけなら 409、2 人なら削除でき記録も消える、同時に 2 件削除しても 1 人残る、他の家族のこどもは 404
- [ ] アプリ: リポジトリの delete、削除ボタン・確認ダイアログ・1 人だけのときの無効化、削除後の選択と再取得
- [ ] アプリ: `LAST_CHILD` のエラー文言
- [ ] テスト: 確認ダイアログ、キャンセルでは削除しない、削除後にホームに戻り別のこどもが選ばれる、1 人だけのときは押せない

## 実装メモ（計画からの変更）
- 日付をタップしたときの詳細はマスの下に出るので、小さい画面でも見えるところまで自動でスクロールする
- マスの高さは文字の大きさに合わせて決める（マスの中の文字の拡大は 1.2 倍まで）
- さかのぼれるのは生まれた月まで（生年月日が分からなければ 120 か月）
- 取得済みの月のキャッシュは「画面から外れてから 5 分」。記録の追加・修正・削除とログアウトで捨てる
- 日付の範囲のスキーマは milk-daily と共用にし、名前を `dailyRangeSchema` に変えた
- 既存の AI の e2e 2 件は「こどもを削除しても回数が戻らない」を確かめるため、こどもを 1 人ずつ作って消していた。最後の 1 人は消せなくなったので、消さないこどもを 1 人先に登録するように直した

## レビュー結果
code-reviewer（3 回）・security-reviewer（2 回）とも、修正後は Critical・High・Medium なし。

### 対応したもの
- Medium: 文字を拡大するとマスが縦にはみ出す（広い画面で 13 px）→ マスの高さを文字の倍率から決める。800 px 幅・1.5 倍のテストを追加
- Medium: マスの読み上げでタップの操作が消える → Semantics に onTap
- Medium: 取得に失敗した月で日付を選ぶと詳細が「読み込み中…」のまま → 失敗時は「読み込めませんでした」
- Medium（2 回目）: 失敗した月を取り直している間に「読み込み中」と「読み込めませんでした」が並ぶ → 状態を waiting / failed の 2 つにまとめた（テスト追加）
- 自分で見つけたもの: 進捗バーがリストの先頭にあり、下にスクロールすると見えなくなる → 月の見出しのすぐ下（リストの外）に固定（テスト追加）
- 自分で見つけたもの: 日付の詳細がマスの下に隠れる → 選んだら見えるところまでスクロール
- Low: 削除の所属確認がロックの外 → 削除の条件に家族の所属を含めた（両レビュー）
- Low: ログアウトしても月のキャッシュが残る → ログアウトで捨て、ログアウト中は取得しない
- Low: 一覧の読み込み中に「1 人だけ」の文言が誤って出る、削除後にこどもの選択が残る、ロックのキー名、今日の日付の取り方、コメント不足
- 足りないテスト: 記録の削除後にカレンダーを取り直す、体重が同じ日に 2 件あるとき最新の 1 件を返す（e2e）

### 受け入れたリスク（対応しない）
- 家族のメンバーなら誰でもこどもを削除できる（利用者の判断）。削除すると記録・AI の結果も消え、元に戻せない。誰が削除したかの記録もない。必要になったら、論理削除（管理者が戻せる）や削除ログを検討する
- API の検証（Node の Intl）と PostgreSQL で知っているタイムゾーン名が違うと 500 になりうる（milk-daily と同じ。情報は漏れない）
- こどもの削除中（記録の連鎖削除の間）は、同じ家族のこどもの登録・削除が待たされる
- カレンダーを開いたまま月をまたぐと、開き直すまで新しい月へ進めない
- 再読み込み中の日付の詳細カードの表示は、月のまとめと同じ条件だがテストはない
